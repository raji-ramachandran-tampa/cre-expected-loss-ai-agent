R3 · Agent memory

Memory management

Implementation: Conversation history, working results and durable preferences are stored separately. Memories carry provenance, scope and expiration.

Business value: Avoids using stale assumptions or leaking context across sessions.

Demonstration: Excludes an expired assumption and retrieves only the active preference.

Limit: Retrieval is tested; live AI use of memory is not yet measured.

R2 · Reliable operation

Failure handling

Implementation: A temporary tool timeout has at most two attempts. Invalid requests return errors; ambiguous provider calls stop.

Business value: Recovers from temporary problems without endless retries or hidden spending.

Demonstration: Injects a timeout, records a retry and completes the EAD workflow.

Limit: Recovery is demonstrated with a synthetic timeout; live provider recovery is not established.

R2 · Reliable operation

Restart and resume

Implementation: SQLite checkpoints and stable call IDs preserve completed work.

Business value: An interruption does not require starting the analysis again.

Demonstration: Stops after a saved tool result and resumes in a separate process.

Limit: Local durability; no distributed or production reliability claim.

R3 · Frameworks, runtimes and orchestration

Tool orchestration

Implementation: LangGraph coordinates decisions, evidence retrieval and the existing EAD model.

Business value: Keeps authoritative calculations in a tested analytical tool.

Demonstration: Runs the comparison and exposes the decision/tool sequence.

Limit: Offline decisions are scripted; live model-driven behavior remains pending.

R4 · Models, tools and prompt assets

Model and tool access

Implementation: Gemini adapter, registered analytical tools and a versioned instruction asset.

Business value: Limits which tools the AI can request and preserves the model boundary.

Demonstration: Shows model configuration, registered tools and source provenance.

Limit: Not enterprise permissions or multi-vendor administration.

R4 · Evaluation frameworks

Objective evaluation

Implementation: Deterministic references check balances and expected errors; run checks require evidence identifiers.

Business value: Measures numerical correctness rather than trusting a convincing explanation.

Demonstration: Runs four model references and the comparison evidence checks.

Limit: No measured live explanation quality or independent model validation.

R6 · FinOps and cost controls

Budget controls

Implementation: Spending allowances are reserved before requests; usage and estimated billing are distinct.

Business value: Stops work before a configured allowance is exceeded.

Demonstration: Sets a zero budget and verifies zero provider requests.

Limit: No account-wide cap or invoice reconciliation.

R6 · Observability

Inspectable activity

Implementation: Ordered events record decisions, tool IDs, latency, failures and usage.

Business value: Lets a reviewer explain what happened and investigate a failed run.

Demonstration: Displays the complete local workflow trace and usage labels.

Limit: Local observability; no centralized monitoring service.

Product leadership, adoption and governance

R1 / R5: The product goal is a reviewable EAD workflow. Acceptance measures cover exact outputs, useful memory retrieval, interruption recovery and controlled spending. User feedback has informed the navigation; enterprise adoption has not been measured.

R6 governance: Synthetic inputs, fixed tool contracts, source provenance and explicit evidence gaps. These are local controls, not a compliance conclusion.

Roadmap: 1. Local capability demonstrations (implemented). 2. Capped live model-driven run and explanation review (pending). 3. More input scenarios and measured usability (proposed).
